# 设计方案（v1.0.0）

## 1. 目标与边界

目标：PAC 的「编辑 → 编译 → 让 Windows 生效 → 与 ZeroOmega 互转」四件事做好，不掺节点管理、订阅、测速。

不做：代理服务本身、订阅解析、流量统计、多用户。

## 2. 数据模型

规则（`data/profiles/<方案>.json` 里的一行）：

```json
{
  "match": "domain_suffix",
  "content": "youtube.com",
  "action": "SOCKS5",
  "proxy": "",
  "fallback_direct": false,
  "note": "",
  "enabled": true
}
```

- `match`：`domain_suffix` / `domain_wildcard` / `keyword` / `url_regex` / `host_regex` / `ip_cidr` / `all`
- `action`：`DIRECT` / `PROXY` / `SOCKS5` / `MIXED`
- `proxy` 留空 = 用方案的 `default_proxy`
- `MIXED` 编译成 `PROXY x:y; SOCKS5 x:y`（可选再追加 `; DIRECT`）

方案（`data/profiles.json`）保存方案清单与当前方案；方案显示名与文件名分离，显示名可用中文。

**真源纪律**：规则真源是 JSON，不是 PAC 文件。PAC 是编译产物；「专业模式手改脚本 → 解析回规则」是尽力而为的便利功能，解析失败时规则表保持不变。

## 3. 编译策略

### 3.1 可读版

```js
if (dnsDomainIs(host, ".youtube.com") || host === "youtube.com") { return "SOCKS5 1.2.3.4:1080"; }
```

优点：跟手写 PAC 一致，好排查。缺点：4000+ 条时文件大、每请求线性试探。

### 3.2 优化版

域名后缀合并成对象查表 + 逐级去前缀：

```js
var PACS_DOM_1_1 = { "youtube.com": "SOCKS5 ...", ... };

function FindProxyForURL(url, host) {
    var d = host, dot;
    while (true) {
        if (PACS_DOM_1_1[d]) return PACS_DOM_1_1[d];
        dot = d.indexOf(".");
        if (dot < 0) break;
        d = d.substring(dot + 1);
    }
    ...
}
```

`www.youtube.com` → 查 `www.youtube.com`（未命中）→ `youtube.com`（命中），最多 4~6 次哈希查找。

**顺序语义**：相邻同类型规则并成一段，段与段之间仍按原顺序执行；「全部流量」之后的内容截断并给警告。这样优化不会破坏「先命中先生效」。

其他类型：通配/正则/关键词/IP 段各自成段，用数组循环或 `isInNet`。**IP 段外层包一层 `/^\d+\.\d+\.\d+\.\d+$/.test(host)`**，避免 `isInNet` 对域名做 DNS 解析（这是 PAC 里最容易被忽略的性能坑）。

### 3.3 编码

- PAC 文件 UTF-8 无 BOM；进入字符串字面量的内容一律转 `\uXXXX`（默认开启），保证某些按 ANSI 读文件的引擎也不会破坏规则值
- 中文只出现在注释里，注释乱码不影响解析
- 只用 ES3 语法（`var` / `function` / `new RegExp` / 数组字面量），已用 Windows JScript（`cscript`）实测能解析

## 4. Windows 生效

写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`：

| 键 | PAC 模式 | 说明 |
| --- | --- | --- |
| `AutoConfigURL` | `file:///.../data/pac_current.pac` | 有值就写，还原时为空则**删除该值**（写空串不等于没配 PAC） |
| `ProxyEnable` | `0` | 与固定代理互斥，必须清零 |
| `ProxyServer` | 原值保留 | 关 PAC 后原来的固定代理还在 |
| `ProxyOverride` | 原值保留 | 同上 |

写完调 `InternetSetOptionW(0, 39, 0, 0)` + `(0, 37, 0, 0)` 刷新。

**备份纪律**：4 个键（含 `AutoConfigURL`）一起备份。用户原本可能用着公司/校园网 PAC，只还原另外三个键等于把它永久删掉。备份同时写 `data/system_proxy_backup.json`，防设置文件损坏。

## 5. ZeroOmega 互转

### 5.1 实测结构（`G:\PAC\OmegaProfile.pac`，4655 行）

```js
var FindProxyForURL = function(init, profiles) {
    return function(url, host) {
        var result = init, scheme = url.substr(0, url.indexOf(":"));
        do {
            if (!profiles[result]) return result;
            result = profiles[result];
            if (typeof result === "function") result = result(url, host, scheme);
        } while (typeof result !== "string" || result.charCodeAt(0) === 43);  // '+' 开头继续跳
        return result;
    };
}("+自动模式", {
    "+自动模式": function(url, host, scheme) { ...190 条... return "+__ruleListOf_自动模式"; },
    "+__ruleListOf_自动模式": function() {
        var FindProxyForURL = function(init, profiles) { ... }("+__tempZeroRuleListPac", {
            "+__tempZeroRuleListPac": function(url, host, scheme) { ...4416 条... return "DIRECT"; }
        });
        return FindProxyForURL;
    }.call(this),
    "+Master":   function(...) { ...本机直连... return "SOCKS5 ***已脱敏***-内网IP:20808"; },
    "+I2P 大洋葱": function(...) { ...本机直连... return "PROXY ***已脱敏***-内网IP:4444"; }
});
```

要点：

1. **嵌套**：第 211 行又出现一个完整的 `var FindProxyForURL = …`，这是「规则列表」壳里嵌的第二个 PAC。所以解析器要**全局收集所有 profile 定义**，不能只扫第一层。
2. **跳转链**：`+自动模式` 的兜底是 `+__ruleListOf_自动模式`，后者是壳，真正的规则在 `+__tempZeroRuleListPac`。
3. **`+Master` 是结果型**：只有「本机 → DIRECT」一条保护 + 一个出口，可以折叠成出口串（脚本头部已统一处理本机直连）。
4. **正则字面量里有 `{` / `}`**：花括号配对必须跳过正则字面量与字符串，否则直接解析错位。

### 5.2 导入算法

```
扫描所有 "名字": function(...) {  → 取函数体（花括号配对，跳过字符串/正则/注释）
对每个函数体：剥离嵌套 PAC，记录 nested_init；提取 if 规则与兜底 return
从入口展开（带栈防环、缓存）：
    规则里的 return "+X"：
        X 是「结果型」（规则≤8条、有具体兜底）→ 折叠成兜底出口
        否则 → 内联 X 的规则 + 一条 all(X 兜底)（与 ZeroOmega「return 即终止」语义一致）
    兜底 return "+X" → 递归展开
host 正则归一：能还原成域名后缀/通配就还原，否则保留 host_regex
```

### 5.3 导出算法

生成与样本同构的 `(function(init, profiles){…})("+自动模式", {...})`；
`compatible` 风格把代理动作指向 `+Master`（多个不同出口自动拆 `+Master_2`…），`flat` 风格每条直接返回代理串。

往返一致性由 `_scaffold/smoke_core.py` 验证（导出再导入，规则数必须相同）。

## 6. 风险与取舍

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| WinINET/IE 对 SOCKS5 支持不完整 | 老程序可能不走代理 | 界面与设置里明示；可切 PROXY / 混合 |
| PAC 体积 | 4000+ 条可读版 526 KB | 默认优化版 363 KB；`file:///` 不涉及下载超时 |
| `isInNet` 触发 DNS 解析 | 每个域名都解析会明显变慢 | IP 段外层加 IPv4 字面量判断 |
| 正则里含 `{n,m}` | 花括号配对错位 | 扫描器跳过正则字面量 |
| 多条件 `&&` | 拆条会改变语义 | 只登记不转换，导入报告里列出来 |
| 折叠 `+Master` 的本机保护 | 依赖脚本头部统一直连 | 头部固定包含 localhost / 127.0.0.1 / ::1 / 纯主机名 |
| 退出还原 | 用户可能希望长期保留 PAC | 设置里可关掉「退出时还原」 |

## 7. 线程与进度

- `PacsWorker(QThread)` 接受 `task(progress) -> result`，进度通过信号回主线程
- 导入/导出/编译/应用/还原全部走 worker
- 进度回调是节流的（每 400 条一次），避免每条规则都刷 UI
